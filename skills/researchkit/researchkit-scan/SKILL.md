# researchkit-scan スキル（R2: 予備調査・広域）

問いの立て方を決める前に、題材の「地図」を作る。すでに誰かが答えている問いを調べ直したり、存在しないデータを前提に問いを立てたりしないためである。ここで集めたものは**問いの立て方（R3）と壁打ち（R4）、仮説（R5）の材料**であり、調査の結論ではない。主張は書かない。

パスは `.researchkit/config.yaml` の `paths` で読み替える。進捗の記録とモードは [`researchkit-bootstrap`](../researchkit-bootstrap/SKILL.md) の §3・§7 に従う。

## 0. 大原則

- **出典のない事実を書かない。** 既存の調査の結論、統計の値、先行研究の結果には、出典（後述の出典 ID か仮の出典の番号）を付ける。出典には URL か書誌情報と参照日を付ける。
- **AI が挙げた文献・統計・レポートは、1 件ずつ実在を確かめる**（steering の基本原則 2）。存在しない論文や、著者・年・誌名・数値の取り違えが起きやすい。
  - 論文: DOI を `https://doi.org/<DOI>` で開くか、出版社のページ、または書誌データベース（Crossref、PubMed、CiNii Research、J-STAGE、Semantic Scholar など）の該当ページで、題名・著者・年・誌名が一致することを確かめる。Google Scholar の検索結果だけでは確かめたことにしない（入口として使う）。
  - 統計: 発表元（府省、自治体、国際機関、業界団体）のページか、e-Stat などの公式の窓口で、表の名前・調査年・単位を確かめる。
  - レポート・記事: 発行元のページで、題名・発行日・発行元を確かめる。有料で本文を読めないものは、公開の要約で確かめた範囲だけを書き、その旨を書く。
  - 確かめられなかったものは「未確認」の表に分け（出典台帳に登録するなら等級 `D`）、根拠にしない。
- **数値を記憶で書かない。** 市場規模、件数、割合は、出典のページで値・単位・年を確かめてから書く。確かめられなかったものは「未確認」と書く。
- **ページを開けない出典**: 取得が拒否されるサイト（403）や、動的に描かれるページは、検索結果の要約か別の窓口（データベースの書誌、発行元のプレスリリース）で確かめ、その旨を書く。検索の要約は固有名詞と数値を取り違えることがあるので、要約だけで確かめたものは、別の出典でもう一度確かめる。確かめられなければ、等級を 1 段下げる（steering「Claude Code のクラウドセッション」）。
- **孫引きをしない。** 記事やまとめが引いている統計・研究は、元の発表に当たる。当たれなければ、「〇〇（記事）による。元の発表は未確認」と書く。
- **見つからなかったことも記録する**（steering の基本原則 6）。検索式、データベース、期間、件数、参照日を「検索の記録」に残す。見つからないことは、それ自体が結果である（「問いがまだ答えられていない」根拠になる）。ただし、存在しないことの証明ではない。
- **既存の記述は消さない。** 再実行したときは、日付つきの新しい節を足す。

### 始める前に（検索の予算）

`$RK budget --step R2` を実行する（単独で題目を 1〜2 個だけ調べるときは `--need <見積もり>`）。`VERDICT: STOP` なら始めずに止まり、新しいセッションで実行するよう案内する（steering「セッションの区切り」）。

## 1. 入力

- `docs/concept/seed.md`（原文、決めたいこと、何が分かれば何を決められるか、問いの言い換え案、調査の論点、選択）
- `docs/concept/core-question.md`（一括質問の回答を含む）
- 引数の追加の観点や資料名
- 既存の `docs/scan/wide.md`（あれば、重複を避ける）
- 既存の調査に取り込んだとき: 既存の文献リスト、リンク集、先行調査のメモ。中身を読み、確かめ直したうえで移し替える。元の資料は動かさず、出典として書く。

`seed.md` がなければ `researchkit-seed` を案内する。

## 2. 出典の扱い（この段階での登録）

R2 で見た資料は多いが、後で根拠に使うものは一部である。そこで、次のように分ける。**推奨は「根拠に使う可能性のあるものは `S000-` で登録する」である。**

| 区分 | 対象 | 置き場所 | ID |
|---|---|---|---|
| 登録する | 根拠に使う可能性のあるもの。目安: 一次資料、査読つき論文、公的統計、企業の公式の開示、信頼できる二次資料（等級 `A`・`B`）で、R5 の仮説や RQ の「想定する情報源」に挙がりそうなもの | `sources/S000-<NNNN>.md`（1 件 1 ファイル） | `S000-0001` から。`$RK sources next 000 --count <k>` で空き番号を取る |
| 仮の出典に留める | 入口として見ただけのもの。検索の要約、まとめ記事、ブログ、Wikipedia、等級 `C` 以下の多く、確かめられなかったもの | `wide.md` の「仮の出典」の表 | `W1` から（`wide.md` の中だけで使う） |

- 登録する出典のフロントマターは、steering の「出典台帳」の項目（`id`、`type`、`title`、`author`、`publisher`、`published`、`url`、`doi`、`accessed`、`grade`、`primary`、`verified_by`、`used_in`）に従う。`verified_by` には確かめた方法（例: 「doi.org で題名・著者・年が一致」「e-Stat の表のページで値と単位を確認」）を書く。`used_in` は、この段階では空のリスト `[]` にする（RQ で使ったときに足す）。本文には、要点（何が書いてあるか）を 3〜5 行で書き、引用は短くし、引用符と頁や節を添える。
- 仮の出典を後で根拠に使うときは、RQ の工程（`researchkit-collect`）で実在を確かめ直し、`sources/` に登録し直す。仮の出典の番号（`W1`）を、RQ の成果物の根拠の欄に書かない。
- 等級 `D`（未確認）のものは登録しなくてよい。登録した場合も根拠に使わない。

## 3. 手順

### ステップ 1: 調査計画

`seed.md` の「調査の論点」と「何が分かれば何を決められるか」から、次の 5 つの調査の問いを作り、`wide.md` の冒頭に書く。系統ごとに、主な検索の窓口（データベース、サイト）と検索語の案を書く。

| 系統 | 調べること | 主な窓口の例 |
|---|---|---|
| A. 既存の調査 | 同じ問い・近い問いに答えている調査報告、業界レポート、白書、調査会社の公開の要約、報道 | 府省の白書、業界団体、調査会社のニュースリリース、報道機関 |
| B. 先行研究 | 学術の研究。まずレビュー論文（系統的レビュー、メタ分析、総説）を探し、そこから主な研究をたどる | Google Scholar（入口）、Semantic Scholar、PubMed、CiNii Research、J-STAGE |
| C. 統計とデータの所在 | 決め方の規則の左辺を測れる統計・データが、どこに、どの粒度・期間・形式・ライセンスであるか | e-Stat、府省・自治体のオープンデータ、国際機関（OECD、World Bank など）、企業の開示（EDINET、IR）、公開データセット |
| D. 用語と定義 | 主な用語の定義、定義の違いで数値や結論がどう変わるか、分類の体系（産業分類など） | 法令・統計の定義、学会の用語集、レビュー論文の定義の節 |
| E. 論点と立場 | 主な主体（企業、研究者、団体）、議論が割れている点、それぞれの立場の根拠、代わりの説明 | レビュー論文の議論の節、報道、業界団体と消費者団体の意見 |

予算の見積もり（`session.estimates.R2`）を超えそうなら、決め方の規則に効く系統（多くは A と C）を先にする。

### ステップ 2: 並行して調べる（任意）

系統ごとに独立しているので、サブエージェント（Agent）で並行して調べてよい。steering の「サブエージェントに任せるとき」に従う（モデルは `subagents.model`、同時に動かすのは `subagents.max_parallel` まで。系統がそれより多ければ組に分ける）。

- サブエージェントには、このスキルの SKILL.md と [templates/wide.md](./templates/wide.md)、`seed.md`、担当する系統、書いてよいファイル（系統ごとの下書き `docs/scan/wide/<系統>.md` と、割り当てた範囲の `sources/S000-*.md`）を渡す。`wide.md` 本体、`auto-decisions.md`、コミットは親が行う。
- 出典 ID の範囲を系統ごとに分ける（例: A は `S000-0001`〜`0099`、B は `S000-0100`〜`0199`、C は `S000-0200`〜`0299`）。親は、先に `$RK sources next 000` で既存の最大の番号を確かめ、その後ろから範囲を割り当てる。
- サブエージェントの報告の中の事実（件数、文献名、数値）は、下書きのファイルと出典のページで確かめてから `wide.md` にまとめる。重複して登録された出典は 1 つにまとめ、使わなかった番号は欠番のままにする。

### ステップ 3: 既存の調査（A）

- 各調査について、題名、発行元、発行日、対象（地域・期間・母集団）、方法（アンケート、推計、聞き取り）、主な結論、入手の可否（公開 / 要約だけ公開 / 有料）、出典を書く。
- **問いとの重なり**を書く。同じ問いに、同じ範囲で答えている調査があれば印を付ける（「すでに答えがある」）。R3 で、その調査をそのまま使うか、範囲や方法を変えて調べ直すかを検討させる。
- 有料で本文が読めないレポートは、購入の候補として「`[人]` の候補」の欄に書く（R4 の RP5 で予算と合わせて決める）。

### ステップ 4: 先行研究（B）

- レビュー論文を優先する。見つかれば、その範囲（期間、対象、含めた研究の数）と結論、限界を書く。
- 個別の研究は、問いに直接かかわるものを 5〜15 件にとどめる。各研究について、著者、年、題名、誌名、DOI、方法（実験、観察、調査、質的）、対象と規模、主な結果、限界を書く。
- 結果が割れている研究は、両方を載せる（E の論点にもつなぐ）。片方だけを載せない（steering の基本原則 7）。
- この段階は系統的レビューではない。検索の網羅性を主張しない。系統的なレビューが要るかどうかは、R7（`researchkit-method`）で決める。

### ステップ 5: 統計とデータの所在（C）

- 決め方の規則の左辺（`seed.md`）ごとに、測れる統計・データを探す。各データについて、名前、提供元、粒度（国、都道府県、企業、個人）、期間と更新頻度、形式（CSV、API、PDF の表）、ライセンス・利用規約、入手の可否（公開 / 申請 / 有料 / 社内）を書く。
- 値はこの段階では取りにいかない。所在と形式が分かれば足りる。目安として確かめた値を書くときは、表の名前・年・単位を添える。
- 見つからなかった指標は、「見つからなかったこと」に書き、代わりの指標（代理変数）の候補を添える。

### ステップ 6: 用語と定義（D）

- 主な用語ごとに、定義の候補と出典、定義の違いで数値や結論がどう変わるかを書く。
- 採用する定義はここで決めない。R4（RP3 範囲）と R10（用語集）で決めるための材料にする。

### ステップ 7: 論点と立場（E）

- 議論が割れている点ごとに、立場、その根拠、主な主体、利害関係（その立場から利益を得る主体か）を書く。
- 問いに対する「代わりの説明」（種が前提にしている因果や構図とは別の説明）を 1 つ以上挙げる。R5 の対立仮説の材料にする。

### ステップ 8: まとめる

1. A〜E で集めた事実を、1 件 1 行のラベルにし、似たものをグループにして見出し（表札）を付け、見出しどうしの関係（対立・因果・包含）を短く書く（川喜田二郎の KJ 法）。
2. 最後に、次をそれぞれ 3 行以内で書く。
   - **すでに分かっていること**（既存の調査と先行研究で、確度の高い答えがある部分）
   - **まだ分かっていないこと**（答えがない、割れている、古い、範囲が違う部分。調査の価値がある場所）
   - **答えるために手に入りそうなもの**（データと文献の所在の要約。手に入らないものも書く）

### ステップ 9: 問いへの影響

調査で、種（`seed.md`）の問いや決め方の規則を揺るがす発見（例: 同じ問いに最近の調査が答えている、決め方の規則の左辺を測るデータが存在しない、用語の定義で結論が逆になる、期限内に入手できない）があれば、「問いへの影響」の節に書く。R3 は、この節を最初に読んで案を作る。

### ステップ 10: 提示

`wide.md` を書き、要点（まだ分かっていないこと、データの所在、問いへの影響、登録した出典の件数）をユーザーに示す。

- **対話モード**: 追加で調べたい観点や資料を聞く（「このままで R3 へ」を推奨案にする）。追加があれば、ステップ 3〜9 を足してから終える。
- **自動モード**: 追加の調査はしない。「すでに答えがある」とした既存の調査と、「問いへの影響」を `docs/auto-decisions.md` に記録する（見直しの優先度: 中。決め方の規則の左辺を測るデータが見つからなかったときは「高」）。サブエージェントとして呼ばれたときは、記録すべき判断を最終回答で返し、記録は親が行う。

系統ごとの詳しいメモが長くなるときは、`docs/scan/wide/<系統>.md` に分けてよい（`wide.md` の表から相対リンクを張る）。

## 4. 出力

- `docs/scan/wide.md`（様式: [templates/wide.md](./templates/wide.md)）
- `sources/S000-<NNNN>.md`（根拠に使う可能性のある出典）
- 任意で `docs/scan/wide/<系統>.md`

Web を調べられない環境では、推測で埋めない。調べるべき項目と理由を `wide.md` に「未調査」として書き、ユーザーに伝える。自動モードでは、その項目の見直しの優先度を「高」にする。

終わったら `researchkit-bootstrap` §3 の形で `R2` を記録する（単独で実行したときも記録する）。

## 5. 完了報告

- 系統ごとの件数（確認済み / 未確認）と、登録した出典の件数（等級別）
- すでに答えがある既存の調査（あれば）
- まだ分かっていないこと、答えるために手に入りそうなもの（手に入らないもの）
- 用語の定義の揺れで結論が変わりうる点
- 問いへの影響
- 使った Web 検索の件数（`$RK budget` の `USED`）
- 次の案内: `researchkit-framing`（R3）
