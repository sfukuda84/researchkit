# 定性調査の進め方（インタビュー・アンケート）

`researchkit-method` が手法を選ぶとき、各 RQ の `plan.md`（Q5 `researchkit-plan`）、収集（Q8 `researchkit-collect`）、分析（Q9 `researchkit-analysis`）が参照する。**実施（インタビュー、アンケートの配布、同意の取得、倫理審査）はすべて `[人]` の作業である。** AI は、ガイドや調査票の設計、文字起こしの整理、コーディング、分析、記録を担う。

出典の等級、確度、倫理と個人情報の規則は憲章（`.researchkit/memory/constitution.md`）に、最低の水準は品質基準（`docs/quality.md`）に従う。法的な判断はしない。迷うものは `[人]` の確認にする。

## いつ使うか

- 理由、動機、使われ方、困りごとなど、まだ言葉になっていないことを知りたいとき（インタビュー）
- ある集団の中での割合や傾向を、決めた質問で数えたいとき（アンケート。集計は `data.md` に従う）
- デスクリサーチやデータ分析の結果に、当事者の説明を添えたいとき（三角測量）

向かない場面: 母集団の割合を少人数のインタビューから推定する、話を聞ける相手がいない、同意を取れない。

## 計画に書くこと（plan.md の節）

| plan.md の節 | 書くこと |
|---|---|
| 手法 | インタビュー（構造化／半構造化／非構造化）、アンケート、その組み合わせ。選んだ理由 |
| データ | 対象者の集め方、謝礼、実施の方法（対面、オンライン）、記録の方法（録音、メモ） |
| 標本 | 対象者の条件、層（例: 利用の頻度）、人数の考え方（飽和、情報力、誤差の幅） |
| 分析の計画 | コーディングの方法（帰納的／演繹的）、手法（テーマ分析、KJ 法など）、コードの確かめ方 |
| 仮説と反証条件 | 仮説を捨てる観測（例: 対象者の半数以上が、仮説の困りごとを挙げない） |
| 検索数の見積もり | 既存の調査票や尺度を探す検索の回数 |
| 倫理と権利 | 倫理審査の要否、同意の取り方、匿名化、データの保存と破棄 |

## インタビューガイド

- **半構造化**を既定にする。聞くことの順番と主な質問を決め、相手の話に応じて深める。
- 構成: 導入（目的、録音と同意の確認、所要時間）→ 答えやすい事実の質問（最近の行動）→ 本題 → 締め（言い残したこと、次の連絡）。
- 質問は、意見や仮定より**具体的な過去の行動**を聞く（「普段どうしますか」より「最後に〇〇したときのことを教えてください」）。
- 誘導しない。仮説を口にしない、答えを含んだ聞き方（「〇〇で困りますよね」）をしない。
- 深める質問を用意する（「それはなぜですか」「例えば」「そのとき何をしましたか」）。
- 1 回の長さ（例: 45〜60 分）と、質問の数の目安を書く。
- 最初の 1〜2 人で試し、分かりにくい質問を直す（直したことを記録する）。

## アンケート票の設計

- 質問は、`spec.md` の「答えの形」と `plan.md` の指標から逆算して作る。使わない質問は入れない。
- 既存の尺度（検証された質問紙）があれば、出典を付けて使う。使用の条件を確かめる。
- **バイアスを生む設問**を避ける。

  | 種類 | 例 | 直し方 |
  |---|---|---|
  | 誘導 | 「便利な〇〇をどう評価しますか」 | 評価語を外す |
  | ダブルバーレル（1 問で 2 つを聞く） | 「価格と品質に満足していますか」 | 2 問に分ける |
  | 黙従傾向（「はい」に寄る） | はい／いいえの質問ばかり | 選択肢の向きを混ぜる、具体的な選択肢にする |
  | 社会的望ましさ | 「環境に配慮していますか」 | 行動を聞く、匿名を明示する |
  | 選択肢の漏れと重なり | 「1〜5 回」「5〜10 回」 | 境界を重ねない、「その他」「わからない」を置く |
  | 順序の効果 | 前の質問が後の答えに影響する | 一般的な質問から具体的な質問へ、選択肢の順を入れ替える |
  | 曖昧な言葉 | 「よく」「最近」 | 回数や期間で聞く |

- 回答の尺度（5 段階など）は、ラベルを全段階に付け、調査の中でそろえる。
- 配布の前に、数人に試しに答えてもらい（`[人]`）、時間と分かりにくさを確かめる。

## 対象者の選び方とサンプルサイズ

- **インタビュー**は、代表性ではなく、問いに答えるための多様さで選ぶ（目的的サンプリング）。層（利用の頻度、立場、地域など）を決め、層ごとに数人を置く。
- 人数は**飽和**（新しいインタビューから新しいコードやテーマがほとんど出なくなること。理論的飽和の考えは Glaser と Strauss, 1967）を目安にする。同じ性質の対象者への研究では、12 人前後で主なテーマが出そろったという報告がある（Guest、Bunce、Johnson, 2006）。対象者の範囲が広いほど、多く要る。
- 研究の目的の狭さ、対象者の特定性、理論の使い方、対話の質、分析の方法から必要な人数を考える「情報力」（Malterud、Siersma、Guassora, 2016）という考え方もある。
- 飽和を目安にするときは、インタビューごとに新しく出たコードの数を記録し、止める判断の根拠にする。
- **アンケート**で割合を推定するなら、許容する誤差の幅から人数を見積もる。単純無作為抽出で、割合を 95% の信頼度、誤差 ±5 ポイントで推定するには、おおよそ 385 人が要る（最も大きくなる p = 0.5 の場合）。ネットの調査パネルなど無作為でない標本では、この計算は目安にすぎないことを書く。

## 同意書と倫理

- 同意書に書くこと: 調査の目的、実施する主体、所要時間、録音・録画の有無、データの使い道と公開の範囲、匿名化の方法、保存の期間と破棄、参加は任意でいつでもやめられること、問い合わせ先、謝礼。
- 同意は実施の前に取り、記録を残す（同意書そのものは個人情報を含むので、リポジトリに入れない）。
- 倫理審査の要否は、所属機関の規程に従って判断する（`[人]`）。医学系の研究は「人を対象とする生命科学・医学系研究に関する倫理指針」などが関わる。
- 未成年や、立場の弱い人（従業員に対する上司など）に聞くときは、断りやすさに配慮する。

## 匿名化

- 対象者は `P01` のような記号で表す。記号と実名の対応表は、リポジトリの外で管理する（`[人]`）。
- 文字起こしから、氏名、勤務先、地名、日付など、組み合わせると個人が分かる情報を取り除くか、ぼかす（例: 「〇〇市」→「関東の政令市」）。
- 引用する発言は、個人が特定されないことを確かめてから使う。
- 出典の台帳（`type: interview`）にも、個人を特定できる情報を書かない（steering の「出典台帳」）。

## 文字起こし

- 録音から文字に起こす。ツールを使うときは、音声を外部のサービスに送ってよいかを、同意の範囲と所属の規程で確かめる（`[人]`）。
- 自動の文字起こしは、固有名詞や数値を誤りやすい。分析に使う発言は、録音と照らして直す（`[人]` か、録音にアクセスできる人）。
- 発言者、時刻、聞き取れなかった箇所（`[聞き取り不能]`）を書く。言いよどみをどこまで残すかを決めておく。
- 匿名化した文字起こしだけを `studies/<NNN-name>/evidence/` に置く。録音と匿名化前の文字起こしは、リポジトリに入れない。

## 分析の手順

### コーディング

- **コード**は、発言の一部に付ける短いラベルである。コードの一覧（コードブック）に、名前、定義、含める例と含めない例を書く。
- **帰納的**（データからコードを作る）か、**演繹的**（仮説や枠組みから先にコードを決める）か、その組み合わせかを `plan.md` で決める。
- グラウンデッド・セオリー（Glaser と Strauss, 1967）の系譜では、Strauss と Corbin が、オープン・コーディング（データを細かく切ってコードを付ける）、軸足コーディング（コードどうしの関係をつなぐ）、選択的コーディング（中心となるカテゴリーにまとめる）の段階を示した。Charmaz は、初期のコーディングと焦点を絞ったコーディングに分ける。コーディングの技法の一覧は Saldaña『The Coding Manual for Qualitative Researchers』が参考になる。
- コーディングの表（発言の ID、対象者、発言の要約か引用、コード）を `studies/<NNN-name>/analysis/` に置く。
- AI がコーディングした場合は、その旨を書く。一部を人が独立にコーディングし、一致の程度（Cohen のカッパ、Krippendorff のアルファなど）を確かめるか、食い違いを話し合って直すことを `[人]` のタスクにしてよい。

### テーマ分析（Braun と Clarke）

Braun と Clarke（2006）が示した 6 つの段階で進める。

1. データに慣れる（文字起こしを読み返し、気づきを書く）
2. 最初のコードを作る
3. テーマを探す（コードをまとめる）
4. テーマを見直す（コードとデータ全体に照らして）
5. テーマを定義し、名前を付ける
6. 報告を書く（テーマごとに、根拠になる発言を添える）

Braun と Clarke は後に、分析者の解釈を重んじる「再帰的テーマ分析」として段階の名前を改めている。どちらに従ったかを書く。

### KJ 法（川喜田二郎）

川喜田二郎が『発想法』（中公新書, 1967）で示した方法である。

1. ラベル作り: 発言や観察を、1 枚に 1 つの内容で短く書く
2. グループ編成: 内容の近いラベルを集め、まとまりに表札（その集まりを一言で表す文）を付ける。これを小さなまとまりから大きなまとまりへ繰り返す
3. 図解化（A 型）: まとまりの関係（因果、対立、相互の関係）を図にする
4. 文章化（B 型）: 図を文章にして説明する

- 先に枠組みを決めずに、データの声から集めることが要である。分類の箱を先に作って振り分けない。
- 図は `analysis/` に mermaid か画像で残し、ラベルと元の発言の対応を表に残す。

### 主張へのつなぎ方

- テーマごとに、何人（`P01` など）から出たかを書く。ただし、少人数のインタビューの人数を、母集団の割合として書かない。
- 反対の例（テーマに当てはまらない発言）も記録し、`findings.md` の「反証・限界」に書く。
- 定性調査だけを根拠にした主張の確度は、憲章の規則に従う（既定では、一般化を含む主張は「示唆」までにする）。

## 記録するもの

| 記録 | 置き場所 |
|---|---|
| インタビューガイド、アンケート票（版と変更の記録） | `studies/<NNN-name>/evidence/` か `plan.md` の付録 |
| 対象者の一覧（記号、層、実施日。個人を特定できる情報は書かない） | `studies/<NNN-name>/evidence/` |
| 同意の取得の有無（記号ごと） | 同上（同意書そのものはリポジトリの外） |
| 匿名化した文字起こし | `studies/<NNN-name>/evidence/` |
| 出典（`type: interview`） | `sources/<ID>.md` |
| コードブック、コーディングの表、テーマの表、KJ 法の図 | `studies/<NNN-name>/analysis/` |
| 飽和の記録（インタビューごとの新しいコードの数） | `studies/<NNN-name>/analysis/` |
| アンケートの回答データ | `data/raw/`（個人情報を取り除いたもの）と `data/manifest.md`。集計は `data.md` |

報告の書き方の確かめには、インタビューやフォーカスグループの研究の報告の指針 COREQ（Tong、Sainsbury、Craig, 2007）がある。

## よくある落とし穴

- **誘導する質問。** 仮説を確かめたい気持ちが質問に出る。
- **意見や仮定の話だけを聞く。** 「使いますか」への答えは、実際の行動と食い違いやすい。
- **聞きやすい相手だけに聞く。** 知り合い、熱心な利用者、社内の人に偏る（選択の偏り）。
- **少人数の結果を割合として書く。** 「8 人中 6 人」を「75% の利用者」と書かない。
- **コードを先に決めて当てはめるだけになる。** 想定外の発言を拾えない。
- **反対の例を捨てる。**
- **匿名化が足りない。** 役職、地域、出来事の組み合わせで個人が分かる。
- **同意の範囲を超えて使う。** 録音を外部のサービスに送る、報告に実名を出す。

## [人] になる作業

- 対象者の募集と日程の調整、謝礼の支払い
- 同意の取得と、同意書の保管
- 倫理審査の申請
- インタビューの実施、アンケートの配布と回収
- 録音と匿名化前の文字起こしの保管、記号と実名の対応表の管理
- 外部のサービスに音声やデータを送ってよいかの判断
- 自動の文字起こしの、録音と照らした確認（録音を AI に渡さない場合）
- コーディングの一部の独立な確認

## 確かめること（手法を決めるとき）

- 所属機関の倫理審査の規程と、要否の判断
- 文字起こしのツールのデータの扱い（保存、学習への利用）
- アンケートのツールの回答データの保存場所と、書き出しの形式
