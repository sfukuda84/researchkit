# 文献レビューの進め方

`researchkit-method` が手法を選ぶとき、各 RQ の `plan.md`（Q5 `researchkit-plan`）、収集（Q8 `researchkit-collect`）、分析（Q9 `researchkit-analysis`）が参照する。データベースの収録範囲や検索の機能は変わるので、**実行のたびに公式のページで確かめる**。「確かめる」と書いた項目は、まだ確かめていない。

出典の等級、確度、引用の規則は憲章（`.researchkit/memory/constitution.md`）に、最低の水準は品質基準（`docs/quality.md`）に従う。

## いつ使うか

- 効果、因果、関係について、学術的な研究がすでにあるとき
- 先行研究の地図（何が分かっていて、何が分かっていないか）を作るとき
- 主張の根拠に、査読つきの証拠が要るとき（憲章の等級 `A`）

レビューの種類を `plan.md` で決める。researchkit の既定は、系統的レビューの手順（検索式、基準、件数の記録）を守りつつ、範囲を絞ったものである。種類と簡略化した点は「限界」に書く。

| 種類 | 目的 | 手順の目安 |
|---|---|---|
| 系統的レビュー | 明確な問いに、利用できる証拠を漏れなく集めて答える | PRISMA 2020（Page ほか, 2021）に沿って報告する |
| スコーピングレビュー | 研究の範囲、概念、空白を地図にする | Arksey と O'Malley（2005）の枠組み、報告は PRISMA-ScR（Tricco ほか, 2018） |
| ラピッドレビュー | 期限内に、手順を簡略化して答える | 簡略化した点（データベースの数、1 人でのスクリーニングなど）を明記する |
| ナラティブレビュー | 専門家の視点で文献を選んでまとめる | 選び方が恣意的になりやすい。researchkit では主な根拠にしない |

## 計画に書くこと（plan.md の節）

| plan.md の節 | 書くこと |
|---|---|
| 手法 | レビューの種類と、簡略化する点 |
| 検索式とデータベース | 問いの枠組み、概念ごとの同義語、検索式（データベースごと）、データベース、期間、言語、文献の種類、補う探し方（引用をたどる） |
| 標本 | 包含の基準と除外の基準（表）、スクリーニングの方法（誰が、何段階で） |
| 分析の計画 | 抽出の項目、質の評価のツール、統合の方法（ナラティブか、簡易のメタ分析か。その条件） |
| 反証条件 | 仮説を捨てる観測（例: 質の高い研究の多数が効果なしを示す） |
| 検索数の見積もり | データベースの数 × 検索式の試行の回数、本文の確認の件数 |

**検索式と基準は収集の前に書く**（steering の原則 4）。収集の後に変えたときは、`plan.md` の「計画の変更」に、変えたことと理由を書く。

## 検索式の作り方

1. **問いを枠組みで分ける。**

   | 枠組み | 要素 | 向いている問い |
   |---|---|---|
   | PICO（Richardson ほか, 1995） | Population（対象）、Intervention（介入）、Comparison（比較）、Outcome（結果） | 介入の効果 |
   | PICo（JBI） | Population（対象）、phenomenon of Interest（関心のある現象）、Context（場面） | 定性研究、経験や認識 |
   | PCC（JBI） | Population（対象）、Concept（概念）、Context（場面） | スコーピングレビュー |
   | SPIDER（Cooke ほか, 2012） | Sample、Phenomenon of Interest、Design、Evaluation、Research type | 定性研究、混合研究 |

2. **概念ごとに同義語を集める。** 日本語と英語、表記ゆれ（「ウェブ」「Web」）、略語、上位語と下位語、データベースの統制語（PubMed の MeSH など）を並べる。`docs/glossary.md` の用語を出発点にする。
3. **ブール演算で組む。** 同じ概念の同義語は `OR` でまとめ、概念どうしは `AND` でつなぐ。`NOT` は、必要な文献まで落とすことがあるので控える。語句の完全一致は `"..."`、語尾の変化は切り捨て（`*`）を使う。使える記号と項目の指定（題名、要旨、キーワード）はデータベースごとに違うので、データベースごとに式を書く。

   ```text
   ("remote work" OR telework* OR "work from home") AND (productivity OR performance) AND (employee* OR worker*)
   ```

4. **試して直す。** あらかじめ知っている重要な文献（数本）が検索に引っかかるかを確かめる。引っかからなければ、同義語や項目の指定を見直す。件数が多すぎるときは、概念を足すか、題名と要旨に絞る。
5. 検索式の確かめ方には、PRESS チェックリスト（McGowan ほか, 2016）がある。重要な RQ では、検索式を専門家（図書館員など）に見てもらうことを `[人]` のタスクにしてよい。

## データベース

| データベース | 運営 | 向いている領域・特徴 |
|---|---|---|
| Google Scholar | Google | 分野を問わず広い。検索式の機能が限られ、結果の再現性が低い。補助に使う |
| CiNii Research | 国立情報学研究所 | 日本の論文、図書、研究データ、プロジェクト |
| J-STAGE | 科学技術振興機構 | 日本の学会誌の全文 |
| PubMed | 米国国立医学図書館 | 医学、生命科学。MeSH で統制語の検索ができる |
| Semantic Scholar | Allen Institute for AI | 分野を問わない。引用関係をたどれる。API がある |
| arXiv | — | 物理、数学、計算機科学などのプレプリント（査読前） |
| OpenAlex | — | 分野を問わない文献の目録。API がある |
| 国立国会図書館サーチ | 国立国会図書館 | 日本の図書、雑誌記事 |

- 有料のデータベース（Web of Science、Scopus、医中誌 Web など）は、機関の契約がある場合だけ使う。検索は `[人]` になることがある。
- **引用をたどる**（スノーボーリング）: 採用した文献の参考文献（後ろ向き）と、その文献を引用している文献（前向き）を確かめる。データベースの検索の補いとして記録する。
- 検索のたびに、データベース、日付、検索式、件数を検索ログに書く。

## 包含と除外の基準

基準は表にし、スクリーニングで機械的に当てはめられる形で書く。

| 項目 | 包含 | 除外 |
|---|---|---|
| 対象 | <例: 成人の会社員> | <例: 学生だけの研究> |
| 介入・現象 | <例: 週 1 日以上の在宅勤務> | — |
| 研究デザイン | <例: 実証研究（実験、観察、定性）> | <例: 論説、意見、会議の要旨だけのもの> |
| 期間 | <例: 2015 年以降の出版> | — |
| 言語 | <例: 日本語、英語> | — |
| 文献の種類 | <例: 査読つき論文、公的機関の報告> | <例: 撤回された論文> |

## スクリーニング

1. **重複を除く。** DOI、なければ題名・著者・年で照合する。
2. **題名と要旨で選ぶ。** 迷ったものは残して全文で判断する。
3. **全文で選ぶ。** 除外した文献は、除外の理由（基準のどの項目か）を記録する。
4. **AI がスクリーニングするとき**は、基準ごとの判定と理由を表に残す。重要な RQ では、一部（例: 無作為に 20 件）を人が独立に判定し、一致の程度（Cohen のカッパなど）を確かめることを `[人]` のタスクにする。
5. 件数を PRISMA 2020 の流れ図の段階ごとに数える（下）。

### PRISMA 2020 の流れ図の件数

PRISMA 2020（Page ほか, 2021, BMJ）の流れ図の段階に合わせて、検索ログに件数を残す。

| 段階 | 数えるもの |
|---|---|
| 特定（Identification） | データベースごと・登録簿ごとに見つかった件数。スクリーニングの前に除いた件数（重複、自動のツールで除いたもの、その他の理由） |
| スクリーニング（Screening） | スクリーニングした件数、除外した件数。全文の入手を試みた件数、入手できなかった件数。適格性を評価した件数、除外した件数と理由ごとの内訳 |
| 採用（Included） | レビューに含めた研究の数と、その報告（論文）の数 |
| ほかの方法 | 引用をたどる、Web サイト、機関などで見つけたものは、別の列で同じように数える |

同じ研究が複数の論文で報告されていることがある。研究の数と報告の数を分けて数える。

## 抽出表

採用した文献ごとに 1 行で、`studies/<NNN>/analysis/` に CSV か Markdown の表で置く。項目は収集の前に決める。

| 項目 | 例 |
|---|---|
| 出典 ID | S002-0014 |
| 著者・年 | <第 1 著者, 年> |
| 国・場面 | <国、業種> |
| 研究デザイン | <ランダム化比較試験 / コホート / 横断 / 定性 / 系統的レビュー> |
| 対象と人数 | <n = 1,250> |
| 介入・曝露と比較 | <内容> |
| 結果の指標と測り方 | <自己申告の生産性、7 段階> |
| 主な結果 | <効果量と 95% 信頼区間、または主なテーマ> |
| 質の評価 | <ツールと判定> |
| 資金・利害関係 | <記載の内容> |
| メモ | <限界、ほかの研究との関係> |

数値は原文から写し、頁と表の番号を `evidence/` に残す。

## 研究の質の評価

研究デザインに合ったツールを使い、ツールの名前と判定を抽出表に書く。

| 研究デザイン | ツール |
|---|---|
| ランダム化比較試験 | RoB 2（Cochrane） |
| 介入の非ランダム化研究 | ROBINS-I |
| コホート研究、症例対照研究 | Newcastle-Ottawa Scale |
| 診断の精度の研究 | QUADAS-2 |
| 系統的レビュー | AMSTAR 2 |
| 定性研究 | CASP のチェックリスト、JBI の評価ツール |
| 混合研究 | MMAT |

- 証拠の全体の確かさを段階で表すなら GRADE がある。GRADE の段階と憲章の確度の段階の対応は、憲章で決める。
- 質の評価は判断を含む。AI が評価したものは、その旨を抽出表に書く。

## 統合

- **ナラティブ統合**（既定）: 研究を、デザイン、対象、結果の方向でまとめ、一致する点と食い違う点、その理由（対象、測り方、質の違い）を書く。手順の参考に、Popay ほか（2006）の指針と、メタ分析をしない統合の報告の指針 SWiM（Campbell ほか, 2020）がある。
- 「有意だった研究の数」を数えて結論を出さない（票数え）。効果の方向と大きさ、研究の質で見る。
- **簡易のメタ分析をする条件**: 問い（PICO）と結果の指標が十分に近い研究が複数あり、効果量とその分散（または信頼区間）を取り出せること。研究の間のばらつき（異質性。I² など）を確かめ、ランダム効果モデルを基本にする。計算はスクリプトで行い（例: R の metafor、Python の statsmodels）、`data.md` に従って `analysis/out/*.json` に出す。研究が少ない（目安として 10 本未満）ときは、ファンネルプロットによる出版バイアスの検討は意味が薄い。条件を満たさなければ、ナラティブ統合にとどめる。

## 実在の確認

AI が挙げた文献は、存在しない、または著者・年・題名・数値の取り違えが起きやすい（steering の原則 2）。採用する文献は 1 件ずつ確かめる。

1. **DOI がある文献**: `https://doi.org/<DOI>` が出版社のページに解決すること、ページの題名、著者、年、誌名が台帳と一致することを確かめる。Crossref の API（`https://api.crossref.org/works/<DOI>`）でメタデータを照合してもよい。`check.py --online` でも到達性を確かめる。
2. **DOI がない文献**: 出版社、CiNii Research、J-STAGE、国立国会図書館サーチなどのページで確かめる。
3. 確かめた方法を、出典の `verified_by` に書く（例: `doi.org で解決、題名と著者が一致（2026-10-03）`）。
4. 確かめられなかった文献は等級 `D` にし、根拠に使わない。
5. **撤回の確認**: 出版社のページの撤回の告知、Retraction Watch のデータベースなどで、撤回や訂正がないかを確かめる。
6. 引用した数値や文は、要旨ではなく本文で確かめる。

## プレプリントの扱い

- プレプリント（arXiv、medRxiv、bioRxiv、SSRN など）は査読前である。等級は憲章に従う（既定では、査読つき論文と同じ `A` にはしない）。
- 査読を経て出版された版があるかを確かめ、あればそちらを出典にする。版によって結果が変わっていることがある。
- プレプリントだけを根拠にした主張は、確度を上げない。その旨を「反証・限界」に書く。

## 記録するもの

| 記録 | 置き場所 |
|---|---|
| 検索式（データベースごと）、日付、件数、PRISMA の段階ごとの件数 | `studies/<NNN>/search-log.md` |
| 採用した文献（等級、DOI、確かめた方法） | `sources/<ID>.md` |
| スクリーニングの判定と除外の理由 | `studies/<NNN>/analysis/`（表） |
| 抽出表、質の評価 | `studies/<NNN>/analysis/`（表） |
| 引用する原文と頁 | `studies/<NNN>/evidence/` |
| メタ分析のスクリプトと出力 | `analysis/` と `analysis/out/*.json` |

## よくある落とし穴

- **存在しない文献。** AI が挙げた文献を確かめずに使う。題名がもっともらしくても、DOI が別の論文を指していることがある。
- **要旨だけで結果を判断する。** 要旨は結果を強めに書きがちである。数値は本文で確かめる。
- **出版バイアス。** 効果があった研究ほど出版されやすい。プレプリント、報告書、登録された試験も探すと偏りを減らせる。
- **言語のバイアス。** 英語だけ、日本語だけで探すと偏る。言語の範囲と理由を書く。
- **同じ研究を重ねて数える。** 同じデータを使った複数の論文を、別の研究として数える。
- **撤回された論文を使う。**
- **相関を因果と読む。** 観察研究の結果を、介入の効果として書く。
- **統計的な有意と効果の大きさを混同する。** 効果量と信頼区間を見る。
- **検索式や基準を後から変えて、記録しない。**

## [人] になる作業

- 有料の論文の入手（機関の購読、図書館の文献複写、著者への依頼）
- 機関の契約が要るデータベースの検索
- 専門家（図書館員、分野の研究者）による検索式や採否の確認
- スクリーニングや質の評価の一部を、人が独立に行うこと（一致の確認）

## 確かめること（手法を決めるとき）

- 使うデータベースの収録範囲（分野、年、言語）と、検索式の記号の扱い
- API の利用条件（Semantic Scholar、OpenAlex、Crossref など）
- 機関の購読で読める範囲
