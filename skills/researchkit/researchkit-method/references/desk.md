# デスクリサーチの進め方（市場・競合・技術）

`researchkit-method` が手法を選ぶとき、各 RQ の `plan.md`（Q5 `researchkit-plan`）、収集（Q8 `researchkit-collect`）、分析（Q9 `researchkit-analysis`）が参照する。データベースやサイトの条件（収録範囲、API、利用規約）は変わるので、**実行のたびに公式のページで確かめる**。「確かめる」と書いた項目は、まだ確かめていない。

出典の等級、確度、引用、数値の規則は憲章（`.researchkit/memory/constitution.md`）に、最低の水準は品質基準（`docs/quality.md`）に従う。

## いつ使うか

- 市場の規模と成長、競合の顔ぶれと位置、規制や制度、技術の現状と動向を、公開の情報で押さえるとき
- 期限が短く、まず全体を広く見たいとき（ほかの手法の前段にもなる）
- 答えの形が「数値（規模、シェア、価格）」「一覧（競合、技術の選択肢）」「比較（軸ごとの違い）」のとき

向かない場面: 因果や効果を確かめたい（文献レビューかデータ分析）、理由や動機を知りたい（定性調査）、公開の情報がほとんどない領域。

## 計画に書くこと（plan.md の節）

| plan.md の節 | 書くこと |
|---|---|
| 手法 | デスクリサーチを使う理由。ほかの手法とどう組み合わせるか |
| データ源 | 当たる情報源の種類と順番（公的統計 → 企業の開示 → 業界団体 → 調査会社の公開の要約 → 報道）。有料の資料を使うか |
| 検索式とデータベース | 検索語（日本語と英語、同義語、社名・製品名の表記ゆれ）、使うサイトとデータベース、期間 |
| 標本 | **定義**（市場の範囲、地域、期間、年度か暦年か、通貨）と、**比較の対象の選び方**（競合をどう選ぶか。例: 売上の上位 5 社＋新しく参入した 2 社） |
| 分析の計画 | 市場規模の推計の方法（トップダウン／ボトムアップ）、比較表の軸、為替と物価の扱い |
| 反証条件 | 仮説を捨てる観測（例: 2 つの方法の推計がどちらも 500 億円を下回る） |
| 検索数の見積もり | 情報源の種類ごとの検索の回数 |

## 収集の手順

1. **定義を固める。** 何を数えるか（市場の範囲、製品の区分）、地域、期間、年度か暦年か、通貨を `plan.md` の定義どおりに確かめる。情報源によって定義が違うことを前提に、定義の違いを記録する。
2. **一次資料から当たる。** 報道や二次資料で見つけた数値は、必ず元の統計・開示・発表にさかのぼる。さかのぼれない数値は、見つけた資料の等級のまま扱い、「原典未確認」と書く。
3. **情報源の種類ごとに当たる。**

   | 種類 | 主な情報源 | 見るところ |
   |---|---|---|
   | 公的統計 | e-Stat（政府統計の総合窓口）、各府省の統計のページ。海外は各国の統計局、OECD、World Bank Open Data | 調査の対象、調査の方法、標本の大きさ、調査の時点、改定の有無、統計表の注記。API の利用には登録が要るものがある（確かめる） |
   | 企業の開示 | EDINET（金融庁。有価証券報告書など）、TDnet（日本取引所グループ。適時開示）、各社の IR（決算説明資料、統合報告書）。米国は SEC EDGAR（10-K など） | セグメント情報、会計期間、会計基準、「市場シェア」などの主張の条件と出典 |
   | 業界団体・公的機関の報告 | 業界団体の統計、白書、審議会の資料 | 会員の範囲（全数か会員だけか）、推計の方法 |
   | 調査会社の公開の要約 | 市場規模の推計のプレスリリース | 推計の方法と前提が書かれているか。本体（有料）は `[人]` |
   | 報道 | 大手の新聞、業界紙、通信社 | 日付、一次資料（発表、統計）への言及。一次資料にさかのぼる |
   | 技術 | 公式ドキュメント、標準（ISO、IETF の RFC、W3C 勧告など）、ソースコードのリポジトリ、リリースノート、脆弱性情報（CVE）、特許（J-PlatPat、Google Patents） | 版と日付、ライセンス、保守の状況（最後のリリース、コミットの頻度、未解決の issue）、ベンチマークの条件 |

4. **出典を台帳に登録する。** `$RK sources next <NNN>` で ID を取り、`sources/<ID>.md` を作る（steering の「出典台帳」）。既存の出典なら `used_in` に足す。Web のページは、参照日を書き、可能なら Internet Archive の Wayback Machine などに保存した URL も控える（ページが消えたり変わったりするため）。
5. **抜き書きを残す。** 使う数値と文は、原文のまま `studies/<NNN>/evidence/` に、出典 ID、頁・節・表の番号、取得日とともに書き写す。表の数値は、単位と注記も写す。
6. **検索ログを書く。** 検索語、サイト・データベース、期間、件数、採用した件数を `studies/<NNN>/search-log.md` に書く。見つからなかった検索も書く。

## 分析の手順

### 市場規模の推計

- **トップダウン**: 大きな統計（例: 業界全体の出荷額）に、対象の割合を掛けて絞る。
- **ボトムアップ**: 顧客の数 × 採用の割合 × 単価 × 頻度のように、積み上げる。
- 可能なら**両方で推計し、差を見る**。差が大きいときは、どの前提が効いているかを書く。
- TAM／SAM／SOM（全体の市場／対象にできる市場／取れる見込みの市場）で分ける場合は、各段の絞り込みの前提を書く。
- **フェルミ推定の前提は表にする。** 1 行 1 前提で、値、根拠（出典 ID か「仮定」）、幅（下限・上限）を書く。結論は 1 点ではなく幅で示す。

  | 前提 | 値 | 下限 | 上限 | 根拠 |
  |---|---|---|---|---|
  | 対象の世帯数 | 5,400 万 | — | — | S001-0002（国勢調査） |
  | 利用の割合 | 12% | 8% | 15% | S001-0005（調査会社の公開の要約）。幅は仮定 |
  | 年間の単価 | 6,000 円 | 4,800 円 | 7,200 円 | 仮定（±20%） |

- 計算はスクリプト（`studies/<NNN>/analysis/`）で行い、結果を `analysis/out/<名前>.json` に出す（`data.md` の「出力」）。前提を 1 つずつ動かしたときの結果の幅（感度）も出す。手で計算する場合は `{N:calc}` を付け、計算式と入力を「計算」の節に表で書く。

### 競合比較表

- 比較の軸は、収集の前に `spec.md` の「答えの形」と `plan.md` から決める。集めた後で、都合の良い軸を足さない（足すときは `plan.md` の「計画の変更」に書く）。
- 各セルに出典 ID と時点を付ける。分からないセルは空欄にせず「不明（<調べた範囲>）」と書く。
- 企業の自社発表（「シェア No.1」など）は、条件（調査の主体、対象、時期）を一緒に書き、第三者の資料で確かめられなければ確度を上げない。

### 時点と単位をそろえる

- 年度と暦年、会計期間の違う企業を並べるときは、そのことを表の注記に書く。
- 時系列で金額を比べるときは、名目か実質かを決める。実質にするときは、物価指数（例: 消費者物価指数）と基準年を書く。
- 通貨を換算するときは、レート、その日付か期間（年平均か期末か）、出典を書く。換算の規則は憲章に従う。

### 技術の比較

- 評価の軸（機能、性能、ライセンス、保守の状況、学ぶ費用など）を先に決め、版と日付を書く。
- ベンチマークの数値は、測った条件（ハードウェア、版、設定）と測った主体を書く。条件の違う数値を並べて優劣を言わない。
- リポジトリのスター数やダウンロード数は人気の目安であり、品質や保守の証明ではない。

## 記録するもの

| 記録 | 置き場所 |
|---|---|
| 出典（等級、参照日、一次資料か） | `sources/<ID>.md` |
| 抜き書き（原文、頁・表、単位、注記） | `studies/<NNN>/evidence/` |
| 検索ログ（見つからなかったものを含む） | `studies/<NNN>/search-log.md` |
| 定義の違いの一覧 | `evidence/` か `findings.md` の「反証・限界」 |
| 推計の前提の表、感度 | `analysis/` のスクリプトと `out/*.json`、または「計算」の節 |
| 比較表（セルごとの出典 ID と時点） | `findings.md` か `evidence/` |

## よくある落とし穴

- **定義の違う数値を並べる。** 市場の範囲、年度と暦年、税込みと税抜き、出荷額と小売額の違いを無視して比べる。
- **孫引き。** 報道やブログが引く統計を、原典を確かめずに使う。数値の転記の誤りや、古い版の数値が混ざる。
- **調査会社の推計を一次資料として扱う。** 推計の方法と前提が公開されていない数値は、等級を上げない。複数の調査会社の数値が大きく違うことは珍しくない。
- **古い統計。** 調査の時点と公表の時点を取り違える。最新の版があるかを確かめる。
- **二重計上。** ボトムアップの推計で、同じ顧客や取引を 2 回数える。
- **生存者バイアス。** 成功した企業や製品だけを見て、撤退したものを調べない。
- **AI の検索の要約を出典にする。** 検索エンジンや AI が生成した要約は、元のページを開いて確かめるまで根拠にしない。
- **「見つからない」を「ない」と書く。** 見つからなかったことは、調べた範囲（検索語、情報源、期間）とともに書く。

## [人] になる作業

- 有料の業界レポート、契約制のデータベース、会員限定の資料の入手（AI はログインしない。入手したファイルを `data/raw/` か `evidence/` に置いてもらい、AI が中身を確かめる）

## 確かめること（手法を決めるとき）

- 使う統計の最新の版、公表の予定、API の登録の要否と利用規約
- EDINET や SEC EDGAR などの開示の API の条件
- 調査会社のプレスリリースの引用・転載の条件
- 技術の公式ドキュメントの版と、標準の最新の版
