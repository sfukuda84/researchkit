# researchkit-findings スキル（Q10: 主張のまとめ・逆流・残作業）

分析の結果を、**読み手が決定に使える主張**にする。主張は 1 つずつ、根拠（出典 ID）、確度、反証・限界と組にして表に書く。主張を書いた結果、前提や仮説が崩れたら、上流の文書にも戻して直す。

パスは既定の配置で書いている。`.researchkit/config.yaml` の `paths` で読み替える。ステップ番号、`$HELPER`、再開、自動モードの共通の規則は [`researchkit-worktree`](../researchkit-worktree/SKILL.md) に従う。`$CHECK`・`$NUM` の意味は steering（`.kiro/steering/research.md`）の「エージェントの行動規範」のとおりである。

## 0. 大原則

- **根拠のない主張を書かない。** 根拠の欄が空の主張、等級が `sources.min_grade` に届かない出典だけの主張は書かない。根拠が足りない問いは「残った問い」に書く（確度 `不明`）。
- **確度をぼかさない。** 確度は憲章の段階で表に書き、本文で「〜と思われる」「〜の可能性もある」で済ませない（steering の原則 5）。
- **反証を隠さない。** 反する根拠、代わりの説明、限界は「反証・限界」の欄に書く。探して見つからなかったときも、探した範囲（検索ログの ID）を書く。
- **仮説を結果に合わせて書き換えない。** 判定は、収集の前に書いた反証条件で行う。棄却した仮説は消さずに判定を記録し、新しい仮説は別の ID で足す（§6）。
- **新しい事実を足さない。** 主張の材料は、Q8 の抜き書きと Q9 の分析の結果だけである。足りなければ、Q8・Q9 に戻る（§7 の残作業）。
- **問いに答える。** `spec.md` の「答えの形」と「判定の基準」に沿って、答えを最初に書く。

## 1. 引数

```text
$ARGUMENTS
```

- RQ の指定は `001` か `001-market-size`。省略したら、今いる worktree のブランチから決める。
- `999`（`999-research-report`）のときは統合モード（§9）で動く。
- `000`（`000-research-foundation`）のときは §10 に従う。
- `--auto` は自動モード（§11）。

## 2. 入力

`spec.md`（問い、決定、答えの形、判定の基準）、`plan.md`（分析の計画、反証条件、確度の付け方、計画の変更）、`tasks.md`、`analysis/`（`analysis.md`、`out/*.json`）、`evidence/`・`search-log.md`・`sources/`、`docs/study/hypotheses.md`・`issue-tree.md`、`docs/questions/`・`seed.md`・`premises.md`、憲章・`docs/quality.md`・`config.yaml` の `confidence.levels`・`sources.min_grade`。分析（Q9）の成果物がなければ `researchkit-analysis` を案内する。表は [references/inputs-outputs.md](references/inputs-outputs.md)。

## 3. 主張の表

様式は [templates/findings.md](./templates/findings.md)。書式は steering の「主張の書式」のとおりで、`check.py` と `numbers.py` が読む。

```markdown
| ID | 主張 | 根拠 | 確度 | 反証・限界 |
|---|---|---|---|---|
| C1 | 国内の〇〇市場は 2025 年に 1,234 億円{N:analysis/out/market.json#size_2025}である | S001-0003, S001-0007 | 可能性が高い | 推計の方法が異なる S001-0011 では 980 億円 |
| C2 | 〇〇市場は 2020〜2025 年に年 8.0%{N:analysis/out/market.json#cagr} 伸びた | S001-0003, C1 | 可能性が高い | 2023 年に統計の定義が変わった（S001-0003 の注記） |
```

- **1 行に 1 つの主張。** 「A であり、B である」は 2 行に分ける。主張は、検証できる平叙文で書く（量・向き・範囲・時点を入れる）。
- **ID** は `C1` から振り、使い回さない。消した主張の ID は欠番にする（後から参照が壊れないように）。
- **根拠** には出典 ID（`S<NNN>-<NNNN>`）か、この RQ のほかの主張の ID（`C1`）を `, ` で区切って書く。抜き書きの番号（`E2`）は根拠の欄に書かない（`analysis.md` でたどれる）。等級 `D` の出典は書かない。
- **数値** には、直後に `{N:<path>#<key>}`（RQ のディレクトリからの相対パス）か `{N:calc}` を付ける。`{N:calc}` は、同じファイルの「計算」の節に式と入力を書く。
- **反証・限界** は空けない。反する根拠、代わりの説明、一般化できる範囲（地域・期間・対象）、計画の変更（データを見た後か）を書く。探して見つからなかったときは「反する根拠は見つからなかった（search-log.md #3、#7）」と書く。
- **因果を言うのは、言える設計のときだけ**にする。相関しか示せないときは「〜と関係がある」と書き、代わりの説明を反証・限界に書く。
- 定性調査の主張は、少数の発言を母集団の割合のように書かない（「8 人中 5 人が〜と述べた」と書き、「利用者の 6 割が〜」と書かない）。

## 4. 確度の付け方

確度は、`plan.md` の「確度の付け方」（判定の基準ごとに収集の前に決めた規則）で付ける。判定の列の形なら、上から順に条件を見て最初に当てはまった行の確度を採る。古い形（確度ごとに条件を並べた表）などで**複数の行に当たるときは、低いほうの確度を採る**（結果を見た後に、高いほうに当たる読み方を選ばない）。読み方は「確度の理由」に書く。そこにない主張は憲章（`.researchkit/memory/constitution.md`）の規則で、憲章にも規則がなければ次の既定で付ける（段階は `config.yaml` の `confidence.levels`）。

| 確度 | 目安 |
|---|---|
| `確実` | 独立した `A` の根拠が 2 件以上で一致し、反する根拠がない。または、公的統計などの `A` の一次資料で直接確かめられる事実 |
| `可能性が高い` | `A` か `B` の根拠があり、反する根拠がないか、反する根拠の違いを説明できる |
| `示唆` | 根拠が `C` だけ、間接的、標本が小さい（少数のインタビューなど）、または反する根拠と拮抗する |
| `不明` | 根拠が足りない。主張の表には書かず、「残った問い」に書く |

- **独立**: 同じ一次資料を引いた 2 つの記事は、1 件と数える（孫引きの重複）。
- **上限**: データを見た後に変えた計画でしか出ない結果は、`示唆` までにする。探索的な分析（結果を見た後に足した分析。レビューの指摘に答えて足したものを含む。出力は `exploratory` の下）の結果は、別の主張にして `示唆` までにし、事前に決めた主張の確度と仮説の判定の根拠にしない（`check.py` の `EXPLORATORY_CONFIDENCE`）。ほかの主張を根拠にした主張は、根拠の主張のうち最も低い確度を超えない。
- 確度を決めた理由が自明でない主張は、「確度の理由」の節に 1 行で書く。

## 5. 答えと判定の基準

`findings.md` の最初に「答え」の節を置く。

1. `spec.md` の「答えの形」に合わせて、問いへの答えを 1〜3 文で書く。小問（`SQ1`〜）があれば、小問ごとの答えの形（数値と幅、比較表など）で答える。各文に主張の ID を添え、確度を書く。
2. `spec.md` の「判定の基準」（`AC1`〜）ごとに、満たしたか（満たした・満たさない・答えが出ない）と、根拠の主張を表にする。「答えが出ない」は、`spec.md` に書いた「答えが出ない場合」の条件に当たるときにだけ使い、理由を「残った問い」に書く。
3. つながる決定（`D1` など）に対して、この答えが何を意味するか（決定を変えるか、どちらに寄せるか）を 1〜2 文で書く。決定そのものは下さない（統合報告と読み手が行う）。

## 6. 仮説ごとの判定

この RQ につながる仮説（`spec.md` の「つながる仮説」）ごとに、`plan.md` の「仮説と反証条件」の行（支持の条件、反証条件、どちらでもない結果の扱い）と、`analysis.md` の「反証条件の照合」をもとに判定する。

| 判定 | 条件 |
|---|---|
| `支持` | 支持の条件に当たる結果が出て、反証条件に当たる結果がなく、その結果を示す主張の確度が `可能性が高い` 以上である |
| `棄却` | 反証条件に当たる結果が出て、その結果を示す主張の確度が `可能性が高い` 以上である |
| `保留` | どちらでもない（`plan.md` の「どちらでもない結果の扱い」に当たる、根拠が足りない、結果が拮抗する、条件に当たる結果が `示唆` どまり、条件が曖昧で照合できない） |

- 判定の表には、仮説、反証条件（`hypotheses.md` の原文）、照合した結果、根拠の主張、判定、理由を書く。
- **`支持` は証明ではない。** 反証の機会を通り抜けた、という意味で書く。
- 反証条件を後から緩めない。条件が曖昧で照合できなかったときは `保留` にし、条件の書き直しを逆流（§7）で `hypotheses.md` に記録する。

## 7. 逆流

結論で前提や仮説が崩れたら、`findings.md` だけを直さずに上流の文書にも戻し、「逆流の記録」に書く。`hypotheses.md` は状態（支持／棄却／保留）と根拠の主張 ID と変更の記録、`issue-tree.md` は答えが出た節、ほかの RQ の `docs/questions/<NNN>.md` は、未着手なら直し、着手済みなら末尾の `## 上流からの変更` に追記する。用語集と backlog も必要なら足す。決定（`D`）や前提（`RP`）そのものが崩れたら書き換えずに報告する（自動モードでは優先度「高」で記録）。追記を選び、マージの競合を避ける。行き先ごとの表は [references/backflow.md](references/backflow.md)。

## 8. 残作業（収束）

`spec.md`・`plan.md`・`tasks.md` を意図の正本とし、成果物とのずれ（`missing`・`partial`・`contradicts`・`unrequested`）を探す。ずれがあれば `tasks.md` の末尾の `## 収束（YYYY-MM-DD）` にタスクを足して実行し、ずれが 0 件になるまで繰り返す。未完了の `[人]` はずれに数えない。取れないデータが原因なら「残った問い」に書く。ずれがなければ `tasks.md` を変えない。書式と手順は [references/backflow.md](references/backflow.md)。

## 9. 統合モード（`999-research-report`）

`999` では、`reports/report.md` の結論と各 RQ の `findings.md` の整合を確かめて `studies/999-research-report/findings.md` を書く（結論の表の写し、整合の表、RQ どうしの食い違い、報告書の側を直す、逆流、公開用の形式の点検、`$CHECK`・`$NUM` の検証）。手順は [references/special.md](references/special.md)。

## 10. `000-research-foundation` のとき

主張は作らない。`findings.md` には基盤の状態と、残作業と残った問いだけを書く。§8 の収束は行う。詳細は [references/special.md](references/special.md)。

## 11. 自動モード（`--auto`）

確度に迷う主張は低い方、仮説の判定に迷えば `保留`。逆流は行って `auto-decisions.md` に記録する。決定・前提が崩れたら書き換えずに優先度「高」で記録する。収束のタスクは足して実行し、予算の STOP・`[人]` 待ち・同じ原因の失敗が 3 回のときは止まる。表は [references/special.md](references/special.md)。

## 12. 仕上げ

1. `$CHECK --rq <NNN>` と `$NUM --rq <NNN>` を実行し、ERROR を 0 件にする。WARN（使われていない出典、古い参照日など）は直すか、理由を完了報告に書く。使われていない出典は、根拠に使わなかった理由（反する根拠として検討した、範囲外だった）が分かるなら残してよい。
2. `tasks.md` の `[人]` 以外がすべて `- [x]` であることを確かめる。

## 13. 出力

出力は `findings.md`（様式: [templates/findings.md](./templates/findings.md)）、逆流した文書、`tasks.md` の `## 収束` の節。次の工程は `researchkit-review`（Q11）。チェックポイントは呼び出し元が記録する。詳細は [references/inputs-outputs.md](references/inputs-outputs.md)。

## 14. 完了報告

完了報告の項目（答えと判定の基準ごとの結果、主張の件数〈確度別〉、仮説の判定、残った問い、逆流と決定・前提の揺らぎ、収束のタスク、`$CHECK`・`$NUM` の結果、統合モードの整合、次の案内）は [references/inputs-outputs.md](references/inputs-outputs.md)。
