# researchkit-review: 詳細（axes.md）

[SKILL.md](../SKILL.md) の本文から移した詳細。本文の要点で足りないとき、ここを読む。見出しは本文と同じ番号を使う。

### 軸 S: Source（出典）

- **実在**: 根拠に使った出典が実在し、たどれるか。URL が開けるか、DOI が解決するか、題名・著者・年・誌名が一致するか。`$CHECK --rq <NNN> --online` の結果を材料にし、主張の確度が高いもの（`確実`・`可能性が高い`）と、決定（`D1` など）に効く主張の出典は、ページを開いて確かめる。
- **一次資料か**: 一次資料に当たれるのに、報道や要約で済ませていないか。二次資料が引く一次資料を確かめずに、一次資料として扱っていないか（孫引き）。
- **日付**: 発行日と参照日。問いの時点に対して古すぎないか（品質基準の鮮度の定め）。改訂版・新しい版が出ていないか。
- **等級**: 憲章の等級の定義どおりか。根拠が `sources.min_grade` を満たすか。等級 `D` を根拠にしていないか。
- **引用と原文の一致**: 抜き書き（`evidence/`）の引用が原文と一致するか、位置が正しいか、数値の単位・母数・期間が原文どおりか。主張が引用の範囲を越えて言っていないか。少なくとも、決定に効く主張の引用はすべて、ほかは抜き取りで照合する。
- **台帳の整合**: `used_in` と実際の参照、必須項目、`verified_by` の書き方。

### 軸 L: Logic（論理）

- **飛躍**: 主張が根拠から言えるか。根拠の言っていないこと（範囲、程度、時点）を足していないか。
- **相関と因果**: 因果を言える設計でないのに、因果の言葉（「〜により」「〜のため」）で書いていないか。交絡、逆の因果、選択の説明を検討したか。
- **一般化**: 標本・地域・期間・対象を越えて一般化していないか。少数の事例や発言から全体を言っていないか。
- **答えの形**: `spec.md` の「答えの形」に答えているか。「判定の基準」の判定が根拠と合っているか。範囲外のことを主張していないか。
- **確度と判定**: 確度が憲章の規則（`researchkit-findings` の確度の付け方）どおりか。仮説の判定（支持・棄却・保留）が反証条件どおりか。
- **主張どうしの整合**: 主張が互いに矛盾していないか。答え・決定への意味と主張が合っているか。

### 軸 C: Counter（反対の証拠と代わりの説明）

- **追加の検索**: 主な主張（決定に効くもの、確度の高いもの）ごとに、反対の証拠と代わりの説明を **Web で新しく検索する**。収集のときと違う検索語（否定の語、反対の立場の用語）、違う言語、違うデータベースを使う。検索した式と結果は、記録の「Counter の検索」の表に書く。
- **検索の十分さ**: `search-log.md` の反証の検索が、`plan.md` の反証条件ごとにあるか。件数と範囲は十分か。
- **反証条件の無視**: 反証条件に当たる結果を、例外や誤差として退けていないか。退けたなら、その理由が根拠を持つか。
- **代わりの説明**: 主張を説明する別の仮説（季節性、定義の変更、制度の変更、景気、測り方の違い）を検討したか。
- 見つかった反対の証拠は、出典の候補として URL と要点を記録に書く。採用するときは、親が `researchkit-collect` の手順（実在の確認、等級、抜き書き）で登録する。
- Counter 軸で行った検索は、採用がなかったものも含めて、親が `search-log.md` にも 1 回 1 行で足す（担当の欄は「AI（Q11 の Counter 軸）」など、メモの欄は記録の「Counter の検索」の番号。反証の検索には「反証の検索（H<n>）」）。レビューの記録だけに残すと、検索ログが原則 6（見つからなかったことも記録する）を満たさず、次の回の Bias 軸が検索の偏りを判断できない。指摘への対応で親が行った検索も同じように足す。

### 軸 B: Bias（バイアス）

- **確証バイアス**: 仮説を支える資料だけを探していないか。検索語に結論が入っていないか（「〇〇 成功」だけで探す、など）。
- **選択バイアス・標本の偏り**: 標本の選び方（便宜的な標本、回答者の自己選択、特定の地域・時期）が結果を偏らせていないか。除外の基準が結果を有利にしていないか。
- **生存者バイアス**: 成功した事例・残った企業・続いている利用者だけを見ていないか。
- **出版バイアス**: 肯定的な結果の研究だけを拾っていないか。灰色文献を探したか（文献レビュー）。
- **スポンサーの利害**: 出典の作り手（企業、業界団体、調査の依頼主）に結果への利害がないか。この調査自体の依頼主の意向（`premises.md` の利害関係）が、結論の書き方に入っていないか。
- **事後の変更**: データを見た後に計画を変えた結果を、主として使っていないか（`plan.md` の「計画の変更」）。

### 軸 N: Numbers（数値）

- **突き合わせ**: `$NUM --rq <NNN>`（報告書は `$NUM --file <path>`）の結果。`{N:...}` の付いていない数値がないか。
- **計算**: `{N:calc}` の計算の表を検算する。割合の合計、増減率、年平均の成長率、単位の換算を確かめる。
- **単位・母数・期間**: 単位（千・百万・億）、割合とポイントの違い、母数（全体か回答者か）、期間（年度と暦年、時点と期間）、名目と実質（物価の扱い）、為替（どの時点のレートか）。
- **再実行**: `commands.analysis` で分析のスクリプトをすべて再実行し、`analysis/out/` の JSON が変わらないことを確かめる（`git diff --stat -- studies/<NNN-name>/analysis/out/` が空）。変わったら、乱数のシード、入力のハッシュ（`data/manifest.md`）、環境の違いを調べる。
- **原文との一致**: 出典から写した数値が、抜き書きの原文と一致するか（Source 軸と分担する。Numbers は値と単位、Source は引用の文）。

### 軸 E: Ethics（倫理・権利。定性調査とデータ分析で足す）

- **同意**: インタビュー・アンケートの同意の記録があるか（`[人]` のタスクの完了の確かめ方）。同意の範囲を越えて使っていないか。
- **匿名化**: `evidence/`、`analysis/`、`sources/`、`findings.md`、報告書に、名前・所属・連絡先など個人を特定できる情報がないか。属性の組み合わせや小さな区分で特定できないか。対応表がリポジトリに入っていないか。
- **ライセンスと利用規約**: `data/raw/` のデータを再配布してよいか（コミットしてよいか）。有料データベース・統計・レポートの利用規約の範囲か。図表の転載の許可。
- **引用の範囲**: 引用が必要な範囲にとどまり、出典が明示されているか。
- **AI 利用の開示**: 憲章の AI 利用の開示の定めを満たすか。
- 法的な判断はしない。判断に迷うものは `[人]` の確認に回す。
