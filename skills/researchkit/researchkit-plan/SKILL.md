# researchkit-plan スキル（Q5: 調査計画）

問いの仕様（何に答えるか）を、調査計画（どう調べ、何を見たら仮説を捨てるか）にする。計画は**収集の前に**書き、収集の後に変えたときは、変えたことと理由を残す（基本原則 4）。結果を見てから分析の方法や判定のしきい値を選ぶと、都合のよい結論に寄る。計画を先に固めるのは、それを防ぐためである（臨床研究や心理学で言う事前登録〈pre-registration〉に当たる）。

ステップ番号、モード、質問の規則は [`researchkit-worktree`](../researchkit-worktree/SKILL.md) に従う。通常は [`researchkit-question`](../researchkit-question/SKILL.md) か [`researchkit-all`](../researchkit-all/SKILL.md) から呼ばれる。チェックポイント（Q5）は呼び出した統括スキルが記録する。単独で実行したときは、最後に `$HELPER checkpoint <RQ_NAME> Q5 "<『ステップ番号』の節の subject>"` を記録する。パスは `.researchkit/config.yaml` の `paths` で読み替える。

## 1. 対象と入力

- 対象: `studies/<RQ_NAME>/plan.md`（以下 `RQ_DIR/plan.md`）。テンプレートは [`templates/plan.md`](templates/plan.md)。
- 前提: `RQ_DIR/spec.md` が Q4 まで明確化済みであること。`[NEEDS CLARIFICATION]` が残っていれば、`researchkit-clarify` を案内する（自動モードでは推奨案で埋めて記録する）。
- 参照:
  - `RQ_DIR/spec.md`（小問 `SQ`、答えの形、判定の基準 `AC`、範囲、用語）
  - `docs/method.md`（この調査で選んだ手法、データ源、分析環境）と、手法の参照文書 `researchkit-method/references/`（`desk.md`、`literature.md`、`data.md`、`qualitative.md`）。**この RQ で使う手法の参照文書は必ず読む**
  - `docs/study/hypotheses.md`（仮説と反証条件）、`docs/study/pilot/`（予備調査で分かった、使える検索語、データの所在、落とし穴）
  - `docs/scan/wide.md`（既存の調査・先行研究・データの所在）、`data/manifest.md`、`sources/`（既存の出典）
  - 憲章、`docs/quality.md`（出典の最低等級、確度の要求、再現性の水準）、`docs/concept/premises.md`（予算、期限、使えるデータとアクセス、倫理）
  - `.researchkit/config.yaml`（`commands.analysis`、`session.estimates`、`sources.min_grade`、`data.max_file_mb`）

## 2. 手順

1. テンプレートを `RQ_DIR/plan.md` に写す。すでにあれば、上書きせずに更新する（収集を始めた後なら、§4 の「計画の変更」の規則に従う）。
2. **手法を選ぶ**: 小問ごとに、`docs/method.md` で選んだ手法の中から使うものを決める（1 つの RQ で組み合わせてよい）。RQ の概要の `**手法**` と違う組み合わせにするときは、理由を書き、概要の側も直す。`docs/method.md` にない手法が要るときは、直さずに止まり、`researchkit-method` の改訂を案内する（自動モードでも止まる）。
3. **手法の参照文書に従って、収集と分析の計画を書く**: 下の §3 の各節を、参照文書の手順と書式で埋める。
4. **仮説ごとの反証条件を書く**: `hypotheses.md` の反証条件を、この RQ で観測できる形（どのデータの、どの指標が、どの値なら捨てるか）に具体化する。支持する条件と反証する条件のどちらにも当たらない結果の扱い（確度を下げる、判定を保留する）も書く。
5. **反対の証拠の探し方を書く**: 仮説に反する証拠と代わりの説明を、どの情報源でどう探すかを書く（基本原則 7）。検索式には、仮説に不利な語を含める（例: 「〜の失敗」「〜の効果なし」「〜の撤退」）。
6. **検索数を見積もる**: 収集（Q8）とレビュー（Q11）の Web 検索の件数を見積もり、`session.estimates` の `Q8`・`Q11` と比べる。大きく超える（目安 1.5 倍）ときは、小問を分けて RQ を割る案か、セッションを分けて進める案を書く。
7. **倫理と権利を書く**: 個人情報、同意、匿名化、引用の範囲、利用規約、有料の資料の扱いを書く。判断に迷うものは `[人]` の作業として挙げる（Q6 でタスクにする）。法的な判断はしない。
8. **憲章と品質基準のチェック**: 各原則と品質基準の項目について、計画が満たすかを表で示す。満たせない項目は、理由と代わりの手当てを書く。正当化できない違反があれば、計画を直す。
9. **残った不明点を片付ける**: 情報源の所在やデータベースの収録範囲などで分からないことは、必要なら Web で確かめる（その前に `$RK budget --need <見積もり>` を実行する。STOP なら止まる）。確かめた結果は「決定の記録」に、決めたこと・理由・比べた代案の形で残す。
10. RQ の概要や `spec.md` と食い違う決定をしたときは、そちらも直す。

> 💬 手法の組み合わせ、標本の大きさ、有料の情報源を使うか、仮説の反証条件の具体化に判断が要る場合は、推奨案（`**Recommended:**`）を添えて質問する。自動モードでは推奨案を採り、`RQ_DIR/auto-decisions.md` に記録する。

## 3. 計画の各節の書き方

| 節 | 書くこと | 主に使う参照文書 |
|---|---|---|
| 手法 | 小問ごとの手法と選んだ理由。`docs/method.md` との対応 | `docs/method.md` |
| 情報源と検索式 | 情報源・データベース、検索式（語の組み合わせ、論理演算子、絞り込み）、期間、言語、想定の件数。公的統計・企業の開示資料・業界レポートなどの所在 | `desk.md`、`literature.md` |
| 包含・除外の基準 | 何を根拠に採り、何を外すか（発行年、研究デザイン、言語、出典の等級、対象の地域）。文献レビューでは、件数の流れ（PRISMA の流れ図に当たる、検索 → 重複除去 → 表題・要旨のふるい分け → 本文の評価 → 採用）を記録する方法 | `literature.md` |
| 標本 | 母集団、抽出の方法、標本の大きさとその根拠、対象者の条件と集め方。定性調査では、目標の人数と、飽和（新しいコードやテーマが出なくなること）の判定の仕方 | `qualitative.md`、`data.md` |
| データ | データの出所、取得の方法、ライセンス、大きさ（`data.max_file_mb` を超えるなら `data/large/`）、前処理の方針 | `data.md` |
| 分析の計画 | 小問ごと（判定の基準 `AC` ごと）に、どの分析で答えるか。指標、比較の方法、図表、スクリプトの置き場（`analysis/`）と出力（`analysis/out/*.json` のキー）、手で計算する数値の扱い（`{N:calc}`） | 4 本すべて |
| 仮説と反証条件 | 仮説ごとに、支持の条件、反証条件、どちらでもない結果の扱い、見る指標とデータ | `hypotheses.md` |
| 反対の証拠の探し方 | 仮説に反する証拠と代わりの説明の探し方。使う情報源と検索式 | `desk.md`、`literature.md` |
| 確度の付け方 | 判定の基準ごとに、どの根拠がそろえばどの確度にするか（憲章の段階に合わせる） | 憲章、`docs/quality.md` |
| 出典 ID | 新しい出典の ID の見込み（`S<NNN>-0001` から）。サブエージェントで並行に集めるなら、範囲の割り当て | steering の「出典台帳」 |
| 検索数の見積もり | Q8・Q11 の見積もりと `session.estimates` の比較 | `config.yaml` |
| 倫理と権利 | 同意、匿名化、引用、利用規約、秘密情報の扱いと、`[人]` の作業 | `qualitative.md`、憲章 |
| 憲章と品質基準のチェック | 原則・項目ごとの判定（満たす／満たさない＋理由） | 憲章、`docs/quality.md` |
| リスクと代わりの手 | データが手に入らない、回答者が集まらないなどの見込みと、その場合の代わり（判定の基準の「答えが出ない」につながるか） | `docs/study/pilot/` |
| 決定の記録 | 計画で決めたことごとに、決定・理由・比べた代案 | — |
| 計画の変更 | 収集の後に計画を変えたときの記録（§4） | — |

- 書き方は具体的にする。「関連する論文を集める」ではなく、データベース名、検索式、期間、件数の見込みまで書く。
- 分析の計画には、**収集の結果を見てから決めること**を残さない。どうしても決められない分岐（外れ値の扱いなど）は、分岐の条件と、それぞれの場合の扱いを先に書く。
- 手法の名前や基準を書くときは、出典となる手法名・提唱者を添える（例: 文献レビューの報告の流れは PRISMA 声明に従う）。不確かな固有名詞は書かない。

## 4. 計画の変更

- 収集（Q8）の前の変更は、本文をそのまま直してよい。
- 収集を始めた後の変更は、本文を直したうえで、「計画の変更」の表に、日付、ステップ、変えたこと、理由、収集の結果を見た後か、影響する判定の基準を書く。古い計画の内容は表の中に残す。
- 結果を見た後に分析の方法や判定のしきい値を変えた場合は、Q10 の主張でその分析を探索的なものとして区別し、確度を 1 段下げるかを検討する（`researchkit-findings`）。

## 5. 000 と 999 の扱い

| RQ | 計画の読み替え |
|---|---|
| `000-research-foundation` | **主張を作らない基盤づくり**なので、仮説と反証条件、確度の付け方、反対の証拠の探し方の節は「対象外（基盤）」と書く。代わりに、基盤ごと（出典台帳、用語集、データの目録、分析環境、検索ログの形式）に、整え方と動作の確かめ方を書く。分析環境は、`commands.analysis` で試しのスクリプトを動かし、`analysis/out/` に JSON が出ることを確かめる計画にする。共通の出典は `S000-` で採番する |
| `999-research-report` | 収集の計画の代わりに、**統合の計画**を書く。取り込む RQ と主張（`<NNN>-C<n>`）、結論を先に書くピラミッド構造（バーバラ・ミント〈Barbara Minto〉の『The Pyramid Principle』による）での構成、決定ごとの結論と確度の付け方、RQ の間で食い違う主張の扱い、限界と次の問いの集め方、公開の形式（`researchkit-publish`。不要ならその旨）を書く。新しい収集はしない（足りない根拠は、新しい RQ として `researchkit-questions` に戻す）。数値の参照は、`reports/report.md` ではリポジトリのルートからの相対パス、`findings.md` では RQ のディレクトリからの相対パス（`../001-.../analysis/out/...`）で書く（steering の「数値の参照」） |

## 6. 完了報告

- `RQ_DIR/plan.md` のパス
- 小問ごとの手法、主な情報源とデータベース、標本の大きさ
- 仮説ごとの反証条件（観測できる形）
- 検索数の見積もりと `session.estimates` との比較（超えるならその対処）
- `[人]` になる見込みの作業（有料の資料、同意、倫理審査、アクセス権など）
- 憲章と品質基準のチェックの結果（満たさない項目があれば、その理由）
- 次の案内: `researchkit-tasks <RQ_NAME>`（Q6）
