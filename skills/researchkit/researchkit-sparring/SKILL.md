# researchkit-sparring スキル（R4: 壁打ち → 前提の確定）

問いの立て方を、イシューツリーと仮説を書き始められる前提に変える。調査の失敗の多くは、範囲、期限、使えるデータ、求める確度が、調べ始めた後で食い違うことから起きる。**推測で埋めない。必須項目が全部埋まるまで続ける。**

パスは `.researchkit/config.yaml` の `paths` で読み替える。進捗の記録とモードは [`researchkit-bootstrap`](../researchkit-bootstrap/SKILL.md) の §3・§7 に従う。

## 0. 大原則

- 前提の根拠にしてよいのは、次の 3 つだけである。
  - (a) `core-question.md`・`seed.md`・`framing.md` に書かれたユーザーの決定（一括質問の回答を含む）
  - (b) このスキルでのユーザーの回答
  - (c) 自動モードで採用した推奨案。`(auto: 仮定)` と明示する
- 予備調査の結果（`wide.md`）は、**選択肢と推奨案の材料**である。ユーザーが採用して、初めて根拠になる。
- 1 回の質問は 4 問まで。**1 問ずつ深掘りする**のが基本で、関連の強い論点だけをまとめて聞く。
- **決定から逆算させる。** 「何を調べたいか」ではなく「その答えで何を決めるか」「どの程度確かなら決められるか」で詰める。網羅したい気持ちで範囲を広げさせない。
- 倫理と個人情報、法令、利用規約について、法的な判断をしない（steering の基本原則 9）。判断が要るものは `[人]` の確認として記録する。
- 採らなかった案は、消さずに `backlog.md` に残す。

## 1. 役の選び方

演じる調査の専門家を、引数または `framing.md` の型と主な手法の見込みから決める。

| 引数の例 | エージェント |
|---|---|
| `market`、`市場`、`競合`、`業界`、`デスクリサーチ`、`desk`、`事業` | `research-market`（市場アナリスト） |
| `academic`、`学術`、`文献`、`論文`、`literature`、`レビュー`、`先行研究` | `research-academic`（学術研究者） |
| `data`、`データ`、`統計`、`分析`、`計量`、`因果`、`予測` | `research-data`（データサイエンティスト） |
| `ux`、`定性`、`インタビュー`、`アンケート`、`ユーザー`、`qualitative`、`観察` | `research-ux`（UX リサーチャー） |
| `general`、`汎用`、手法が決まっていない・複数にまたがる | `research-analyst`（汎用の調査の専門家。読めなければ下の 2） |

1. `~/.myai/sparring/agents/<エージェント>.md` と、その定義が指す共通規範（`~/.myai/sparring/common-persona/` の下のファイル）があれば読む。フロントマターより下の本文を、この会話での振る舞いの指示として採用する。衝突したら役の側を優先する。ただし、**このスキルの手順（必須項目、記録、自動モード）が優先する**。定義に「文書を書かない」「要約を返さない」とあっても、`premises.md` への記録は行う。
2. 読めなければ（定義がまだない場合を含む）、その旨を伝えたうえで、汎用の調査の専門家として次の要点で進める。
   - 1 ターンは、短い所感といちばん効く問い 1 つ。質問を並べ立てない。
   - 発散 → 構造化 → 批判 → 検証の設計、の 4 つの段階を切り替え、切り替えるときに宣言する。
   - 良い部分も同じ精度で言う。指摘には必ず代替案を付ける。
   - 既存の調査や統計は具体名で引く。ただし数値や書誌の細部は記憶で断言せず、`wide.md` か WebSearch で確かめる。
   - 期限と予算で実行できない案を出さない。
   - 範囲を広げて逃げない。決定に効かない範囲は削る案を出す。
3. 主な手法が曖昧なら、推定して一言確かめるだけにする。手法を問う質問から始めない。会話の中で主な手法が動いたら（例: デスクリサーチのつもりがインタビューが要ると分かった）、一言告げて役の切り替えを提案する（勝手に切り替えない。自動モードでは切り替えず、最初の役のまま進める）。

## 2. 必須項目

`premises.md` の充足状況表で、各項目の状態を **確定 / 対象外 / 未決** で管理する。`core-question.md`・`seed.md`・`framing.md` に具体的に書いてある項目は、出典を記録して「確定」にし、聞かない。

| ID | 項目 | 埋まったと言える状態 |
|---|---|---|
| RP1 | 読み手 | 主な読み手（決める人）と、ほかの読み手、それぞれの前提知識（専門用語がどこまで通じるか）が決まっている |
| RP2 | 決めたいこと | `seed.md` の D1〜 が確定し、決め方の規則（何が分かれば何を決められるか）に読み手が合意している。決定を変えない論点が外されている |
| RP3 | 範囲 | 地域、期間（データの対象期間）、対象（業界、母集団、製品）、比較の対象、範囲外（扱わないこと）が決まっている。主な用語の定義（`wide.md` の D）のどれを採るかの方針がある |
| RP4 | 期限 | 最終成果物の期限と、その日付を決める出来事、途中で見せる時期（あれば）が決まっている |
| RP5 | 予算 | 有料の資料・データ・論文に使える金額（なしでもよい）、人の作業にかけられる手間、Web 検索のセッション数の見込みが決まっている |
| RP6 | 使えるデータとアクセス | 公開のデータ、社内のデータ、有料のデータベース、インタビューやアンケートの相手のうち、何が使えるか、誰がアクセスの手続きをするかが決まっている |
| RP7 | 要求する確度 | 決定に要る確度（例: 「可能性が高い」以上なら決める）と、確度が足りないときの扱い（決定を延ばす、幅で示す）が決まっている。数値なら許せる誤差の目安がある |
| RP8 | 成果物の形式 | 最終成果物の形式（報告書、スライド、1 枚のメモ、データの表）、分量の目安、構成の要望（結論を先に、など）が決まっている |
| RP9 | 倫理と個人情報 | 人を対象にする調査（インタビュー、アンケート、観察）をするか、するなら同意の取り方、匿名化、倫理審査の要否（判断する人）、個人情報と社外秘の扱いが決まっている。しなければ「対象外」にし、その旨を書く |
| RP10 | 利害関係 | スポンサーや依頼者の意向、結論に利害を持つ人、調査する側の利害（自社製品の比較など）と、その開示の方法が決まっている。なければ「なし」と確かめて確定にする |
| RP11 | 言語 | 調べる資料の言語（日本語だけ / 英語も / ほかも）、最終成果物の言語が決まっている |
| RP12 | 既知の制約 | 上に入らない制約（使ってはいけない情報源、社内の規程、公開してはいけない範囲、AI の利用の制限と開示の要否、使える道具）が挙がっている。なければ「なし」と確かめて確定にする |

## 3. 手順

```text
1. 読み込み → 2. 充足判定 → 3. 診断（最初の 1 回） → 4. 壁打ち（未決がなくなるまで） → 5. 確定の提示 → 6. 書き出し
```

1. **読み込み**: `core-question.md`、`seed.md`、`framing.md`、`wide.md`、既存の `premises.md` と `backlog.md` を読む。既存の調査に取り込んだときは、既存の企画書・依頼書・合意のメモも読み、書いてあることを質問し直さない。
2. **充足判定**: 必須項目表を作り、確定・未決を判定する。
3. **診断**: 最初の 1 回だけ、選んだ問いの立て方を専門家の役で診断する。効いている点、危うい点（とくに、範囲の広すぎ、期限と証拠の入手の食い違い、決定に要る確度と手に入る証拠の食い違い、人を対象にする調査の負担）、最初に決めるべきことを示す。
4. **壁打ち**: 未決の項目を、RP2 → RP1 → RP3 → RP4 → RP7 → RP6 → RP5 → RP9 → 残りの順で優先して聞く。決めたいことと読み手が、範囲と確度の選択肢を決めるためである。
   - 各問に選択肢を 2〜4 個付け、推奨案を先頭に `(Recommended)` 付きで置く。予備調査に基づく選択肢には、説明に出典を添える（例: 「統計 S000-0201 は都道府県別までなので、地域は都道府県単位が現実的」）。
   - 回答から新しい論点が出たら、該当する項目を「未決」に戻すか、項目を足す（RP13 以降。足した理由を書く）。
   - **ラウンドを終えるたびに `premises.md` を更新する**（充足状況表と質疑記録）。中断しても再開できるようにするためである。
   - 質疑記録は `#### Q<n>（ラウンド n）— <項目 ID>` の形で書く。
   - RP2 で決めたいことが変わったら、`seed.md` の決定（D）の更新を `researchkit-seed` の更新モードで行う（ID を振り直さない）。範囲（RP3）や決めたいこと（RP2）が大きく変わった場合は、`researchkit-scan` での再調査を提案する（`researchkit-bootstrap` §4「R4 → R2（戻り）」）。
   - ユーザーが「この項目は後で決める」と明示した場合に限り、未決のまま進めてよい。その場合は `[NEEDS CLARIFICATION: …]` を付けて残し、完了報告に挙げる。RP1・RP2・RP3・RP4 は、後の工程（イシューツリー、仮説、RQ の切り方）が前提にするので、未決のまま進めない。
5. **確定の提示**: 全項目の確定内容を表で示し、「この前提で進める / 修正する」を確かめる。
6. **書き出し**: `premises.md` を最終版にし、採らなかった案（削った範囲、見送った問い、使わないと決めた情報源）を `backlog.md` に足す。調査の名前（仮題）を決めたり変えたりしたら、`.researchkit/config.yaml` の `title` も更新する。

### 自動モード

- 未決の項目は、`core-question.md`・`seed.md`・`framing.md`・`wide.md` から推奨案を作って採用し、「確定」にする。1 問ずつ深掘りする手順は、自動モードでは 1 ラウンドにまとめてよい（Q-ID は項目ごとに振る）。
- 質疑記録は `#### Q<n>（ラウンド 1, auto）— <項目 ID>` とし、回答の頭に `(auto: 仮定)` を付けて根拠を書く。
- RP1（読み手）、RP2（決めたいこと）、RP3（範囲）、RP4（期限）、RP5（予算）、RP9（倫理と個人情報）、RP10（利害関係）は、見直しの優先度を「高」にして `docs/auto-decisions.md` に記録する。
- 根拠のない推奨案は、範囲が狭く、人の作業と費用が少なく、後から広げやすい選択肢を採る（例: 地域は 1 か国、資料は公開のものだけ、有料の資料は買わない、人を対象にする調査はしない〈RP9 は「対象外」〉、確度は「可能性が高い」以上を求める）。期限が分からなければ、期限は決めず「なし（仮定）」とし、RQ の数を少なくする方針を書く。

## 4. 出力

- `docs/concept/premises.md`（様式: [templates/premises.md](./templates/premises.md)）
- `docs/concept/backlog.md`（様式: `researchkit-questions` の [templates/backlog.md](../researchkit-questions/templates/backlog.md)。既存の候補は消さず、状態だけを変える）

終わったら `researchkit-bootstrap` §3 の形で `R4` を記録する（単独で実行したときも記録する）。

## 5. 完了報告

- RP1〜RP12 の確定内容の要約（未決のまま残した項目があれば、その一覧）
- `[人]` の確認が要る項目（倫理審査の要否、データのアクセスの手続き、有料の資料の購入）
- 演じた専門家（定義を読めたか）
- backlog に足した件数
- 次の案内: `researchkit-hypothesis`（R5）
